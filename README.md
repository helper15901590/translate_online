# 网页视频转文字 · Chrome 扩展

捕获当前标签页正在播放的视频/音频，交给阿里云百炼（DashScope）识别成文字，**逐段翻译成中文**，并提取**生词的音标和释义**，最后导出 **Markdown**。

不需要下载视频文件，不需要额外装 ffmpeg，也不依赖任何自建服务 —— 音视频数据不出浏览器，只把切好的音频片段发给 DashScope。

特别适合看英文技术视频、讲座、播客：一边听一边就有中英对照稿，生词也顺手整理好了。

---

## 它能做什么

- **捕获标签页音频**：点一下按钮，正在播放的视频声音就被接管，页面照常播放、照常能听见。
- **边播边转，实时出字**：音频按 30–90 秒切片滚动送去识别，长视频不用等播完就有结果。
- **逐段翻译**：每个识别分片单独送一次文本模型，所以**译文和原文天然一段对一段**，不存在整篇翻译对不上号的问题。
- **生词提取**：按你设定的难度基线挑出生词，给出音标（可选英式/美式/两者）、词性和**贴合本句语境**的释义。
- **导出 Markdown**：一次产出一个 `.md`，包含全文、译文、逐段对照、生词汇总四种视图。
- **识别和翻译并行跑**：第 N 段在翻译时，第 N+1 段可以同时识别，整体耗时接近只做识别。
- **失败自动重试**：单个片段失败会重试 3 次，最终失败也只影响那一段，其他内容照常保留。
- **API Key 只存在本地**：保存在 `chrome.storage.local`，除 DashScope 之外不发给任何第三方。

## 安装

还没上架 Chrome 应用商店，用「加载已解压的扩展程序」安装：

```bash
git clone https://github.com/helper15901590/translate_online.git && cd translate_online
```

1. 打开 `chrome://extensions/`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择本仓库根目录（含 `manifest.json` 的那一层）

需要 **Chrome 116 或更高版本**。

## 配置

第一次使用时，点扩展图标 → 右上角齿轮，或者直接在扩展列表里点「扩展程序选项」：

1. 到 [阿里云百炼控制台](https://bailian.console.aliyun.com/) → 「API-KEY 管理」创建一个 API Key
2. 把 Key 填进设置页的「DashScope API Key」
3. 选对「服务地域」——**北京站和国际站的 Key 互不通用**，选错了会报 401
4. 点「测试连接」，出现绿色的「连接正常」就说明通了

「测试连接」会真的跑两件事：往 DashScope 发一段 1 秒静音验证语音识别，再拿一句真英文跑完整条翻译链路（顺便验证模型的 JSON 输出能不能正常解析）。

### 翻译与生词

同一个设置页往下有「逐段翻译与生词」一栏：

- **翻译模型**：默认 `qwen-plus`，追求速度可以换 `qwen-flash`。它和语音识别是两个独立配置，用的是同一个 API Key。
- **译文语言**：默认中文。如果和「音频语言」是同一种，插件会**自动跳过翻译**，不会白花请求 —— 所以看中文视频时不用手动关。
- **音频语言**（在上面的「识别参数」里）：默认是**自动检测**，这样装好就能直接翻英文视频。指定具体语言能让识别略微更准一些（官方文档也这么说），代价是换一种语言的视频时要记得改回来。
- **生词提取**：可以只挑生词、挑全部值得记的词、或完全关掉。
- **难度基线**：按 CET-4 / CET-6 / 雅思托福筛，低于基线的常见词不会被挑出来。默认 CET-6。
- **每段上限**：默认 6 个，按重要性排序。
- **音标**：美式、英式，或两者都给。

不确定效果如何，就先点「测试连接」，它会打印一句译文和几个生词示例。

## 使用

1. 打开有视频/音频的网页，让它开始播放
2. 点扩展图标 → 「开始转录」
3. 页面右下角会出现一个悬浮条，显示已识别的段数和时长，也可以直接在上面点「停止」

识别结果会按时间顺序实时出现在弹窗里：原文一行、译文一行（带左侧细线）、生词若干行。译文通常比原文晚几秒出现，会先显示一段加载中的占位。转录过程中可以随便切标签页，录制不会中断（但被捕获的那个页面要保持播放）。停止之后，用弹窗里的「复制 Markdown」或「下载 .md」取走结果。

## 它是怎么工作的

```
┌─ popup ────────┐   点「开始转录」
│  控制台 + 结果  │──────────────────┐
└────────────────┘                  ▼
                            ┌─ Service Worker ────────────┐
                            │ chrome.tabCapture           │
                            │   .getMediaStreamId(tabId)  │
                            │ 读设置 / 写 chrome.storage   │
                            └──────────┬──────────────────┘
                          streamId + settings
                                       ▼
   ┌─ Offscreen 文档（不显示，但一直在跑） ─────────────────────┐
   │                                                          │
   │  getUserMedia({chromeMediaSource:'tab'})                 │
   │        │                                                 │
   │        ├──────────────► AudioContext.destination         │
   │        │                （把声音还给扬声器，否则标签页静音）│
   │        ▼                                                 │
   │  AudioWorklet ──► 原始 PCM ──► 缓冲                      │
   │                                  │                       │
   │                    攒够 60 秒 → 找最近的静音处下刀         │
   │                                  │                       │
   │                    重采样 16kHz → 编码 WAV → base64       │
   │                                  │                       │
   │              ┌───────────────────┴──────────────────┐    │
   │              │  第 N 段  qwen3-asr-flash  语音识别   │    │
   │              │              ↓                     │    │
   │              │  第 N 段  qwen-plus  翻译 + 提取生词  │    │
   │              └───────────────────┬──────────────────┘    │
   │                                  │  ◄── 与此同时，第 N+1 段 │
   │                                  │      正在走同一个流程    │
   │              会话状态 ──► SW ──► chrome.storage.local     │
   └──────────────────────────────────┬───────────────────────┘
                                      │ storage.onChanged
                                      ▼
                            popup / 页面悬浮条 自动刷新
```

几个关键的实现选择，以及为什么：

**为什么捕获音频流，而不是去抓音频文件。**
播放器里的音频常常不是单个可下载的文件——YouTube 走 DASH 把音视频分成两路，B 站会把音频切片并加密。想拿到「原始文件」就得用调试器协议嗅探网络请求、解密、再拼装，每换一个网站就可能失效。这里改用 `tabCapture` 捕获标签页的输出音频：对任何网站都一样有效，代价是要实时播放一遍（不能静音着快进转写），以及 DRM 内容拿不到声音。

**为什么翻译按分片单独调，而不是整篇翻一次。**
整篇一次翻看起来省请求，但长文一对几千字就必然对不齐——模型会自行合并、拆分、漏译，最后你根本分不清哪句译文对应哪段原文。按分片翻，**对齐是结构上保证的**，而且第 N 段翻译失败只丢这一段，其他照常。代价是请求数变多，但每段文本都很短，这部分开销可以忽略。

**为什么翻译和识别要分成两条流水线。**
串行做的话总耗时 = 识别 + 翻译，用户要等两倍时间才看得见第一段译文。拆成两条各自串行的队列后，第 N 段的翻译和第 N+1 段的识别同时跑，总耗时接近 `max(识别, 翻译)`。两条队列内部仍然串行，所以顺序和原文时间轴始终一致。

**为什么翻译要求模型返回 JSON，又为它准备了三层兜底。**
译文和生词要在一次请求里同时拿到，只能用结构化输出。DashScope 的 `response_format: {type:'json_object'}` 有两个坑：**消息里必须出现 "JSON" 这个词**（否则直接 400），而且它**只保证语法合法、不保证字段名**——所以字段结构必须在提示词里写死。即便如此模型偶尔仍会裹一层 ` ```json ` 代码块或多说一句话，所以解析器是逐级降级的：直接解析 → 剥代码块 → 扫描配平的花括号。真的全都失败时，退化成「整段就是译文、没有生词」，而不是把这一段丢掉。

**为什么用 AudioWorklet 而不是 MediaRecorder。**
MediaRecorder 输出的是 WebM/Opus，而且除了第一个分片之外，后面的分片都不是能独立解码的完整文件——没法切成一段段单独送去识别。AudioWorklet 直接拿浮点 PCM，每片都能自己编码成一个完整的 WAV。

**为什么切片要在静音处下刀。**
固定按 60 秒硬切，很容易正好切在一个词中间，让边界上的两段都听不清。代码会在目标切点前 2 秒内找能量最低的 150ms 窗口，把刀落在那里，显著减少断句错误。

**为什么捕获后要重新接一遍扬声器。**
Chrome 的 `tabCapture` 会把原标签页静音——因为音频被交给你了。所以 offscreen 文档必须把音频同时接到 `AudioContext.destination`，否则录制期间用户什么都听不见。可以在设置页关掉这个行为。

**为什么切片要重采样到 16kHz。**
语音识别的标准采样率就是 16k，用 48k 只会让请求体积翻三倍而识别效果没有提升。60 秒 16kHz 单声道 WAV 约 1.9MB，base64 后约 2.6MB，稳稳落在 10MB 限制内。

**为什么识别请求发在 offscreen 文档里，而不是 Service Worker 里。**
一是 MV3 的 Service Worker 随时会被回收，而 offscreen 文档在录制期间一定活着；二是 `chrome.runtime` 的消息走 JSON 序列化，`ArrayBuffer` 根本传不过去，几 MB 的音频字符串来回搬运纯属浪费。

但这里有个反直觉的坑：**offscreen 文档里只有 `chrome.runtime` 一个扩展 API 可用**，`chrome.storage` 是 `undefined`。所以设置要由 Service Worker 读好、随启动消息一起传进去；录制过程中产生的会话状态和导出请求，也都发回 Service Worker 代劳。`tools/selftest.mjs` 里有一条测试专门盯着这件事，防止以后不小心又在 offscreen 里写下 `chrome.storage`。

**为什么不用实时语音识别的 WebSocket。**
DashScope 的 `paraformer-realtime-v2` 要求鉴权信息放在 WebSocket 握手的 `Authorization` 请求头里，而浏览器的原生 `WebSocket` 构造函数只接受 URL 和子协议，**无法设置自定义请求头**。要走这条路必须自建一个后端代理，那就违背了「纯前端、零部署」的初衷。所以选择同步接口 + 分片。

## 已知限制

| 限制 | 说明 |
| --- | --- |
| **页面必须是 HTTPS** | Chrome 要求被捕获的标签页是安全来源（secure origin）。`http://` 的页面会直接失败。 |
| **DRM 内容录不到声音** | Netflix、Disney+、部分付费课程等使用 Widevine 加密，`tabCapture` 拿到的是静音。 |
| **一次只能录一个标签页** | `tabCapture` 的语义就是这样。再点一次「开始转录」会先停掉上一个。 |
| **单次请求 10MB / 5 分钟** | 模型同步接口的硬限制。默认 60 秒一片，远低于上限；即使用户把分片调到 300 秒，代码也会自动二分拆分以避免超限。 |
| **识别按下刀前的静音点切片** | 极端情况下（连续演讲、无停顿）可能切在词中间，导致边界处丢一两个字。把「分片时长」调大能减少切点数量。 |
| **没有音频时不会报错** | 页面静音播放时照样会走完流程，只是识别结果为空。 |
| **翻译模型必须支持 JSON 输出** | 插件靠 `response_format: {type:'json_object'}` 一次性拿到译文和生词。少数模型不支持，会报参数错误，换 `qwen-plus` 或 `qwen-flash` 即可。 |
| **译文质量受识别质量影响** | 识别错的地方，翻译只能靠上下文猜。提示词里已经要求模型修正明显的同音词错误，但猜错的情况无法完全避免。 |

## 计费

两条链路分别计费，都从你的百炼账户扣：

- **语音识别**按**音频时长**算（不是按字数）。看了一小时的视频就是付一小时的钱。调小「分片时长」不会增加费用——总时长不变，只是请求次数变多。
- **翻译**按**token**算，每段一次请求。一小时英文视频大约对应 1 万字左右的文本，用 `qwen-plus` 的话这部分花费通常远低于识别费用。

想省钱可以：把「翻译模型」换成 `qwen-flash`；在设置页把生词提取关掉（少一个字段，输出 token 更少）；或者干脆关掉翻译只做转录。

具体单价见[百炼控制台](https://bailian.console.aliyun.com/)，新账号通常有一定的免费额度。

## 常见问题

**「API Key 无效或没有该模型的权限」**
十有八九是地域选错了。北京站的 Key 只能在 `dashscope.aliyuncs.com` 用，国际站的只能在 `dashscope-intl.aliyuncs.com` 用，两边不通用。

**「无法捕获该标签页音频」**
依次检查：页面地址是不是 `https://`；页面是不是真的在出声；有没有录屏软件、会议软件正占用这个标签页。

**录制时听不到声音**
到设置页确认「录制时保持页面声音外放」是勾上的。

**识别结果有重复**
把设置页的「把上一段的识别结果作为上下文」关掉。开启后跨片段用词更连贯，但小概率让模型把上下文也一并「听」出来。

**专有名词老是识别错**
在设置页的「热词 / 上下文提示」里把人名、术语、产品名填进去，能明显降低这些词的错误率。

**生词提取得太多 / 太少**
调「难度基线」。「大学英语六级以上」会滤掉大部分常见词；如果你基础较好，可以选「雅思 / 托福级别」；想要全部实词就选「所有值得记的词和搭配」，同时把「每段上限」调大。

**一条译文都没有，也没有生词**
先看设置页的「音频语言」。如果它被设成了和「译文语言」同一种（比如音频语言选中文、译文语言也是中文），插件会**正常地跳过翻译**——中文视频配中文译文没有意义。想让英文视频出译文，把音频语言留成「自动检测」或选英文即可。

**生词里的音标是空的**
个别模型对音标字段会偷懒。换成 `qwen-plus` 通常就正常了；设置页的「测试连接」会打印一条生词示例，可以先用它验证。

**译文看起来是「整段没有结构」**
说明模型没按 JSON 返回，插件已退化成纯译文模式，这一段会丢掉生词但译文保留。换一个翻译模型可以解决。段落上会显示「模型未返回结构化结果」。

**录到一半结果没了**
浏览器回收后台页面会导致录制中断，中断的会话会被标记出来但已识别的部分会保留在 `chrome.storage.local` 里。长时间录制时避免同时开太多标签页。

## 开发

没有构建步骤，改完代码在 `chrome://extensions/` 点一下刷新即可。

```bash
node tools/selftest.mjs
```

跑 66 项自测：重采样、WAV 编码、base64、识别与翻译两条链路的请求构造和响应解析、错误重试策略、JSON 提取与降级、生词清洗与去重、Markdown 的单语/双语两种渲染，外加打包完整性检查——manifest 引用、import 路径、HTML 资源路径、源码里的控制字符、权限白名单，以及三条专门防踩坑的：**offscreen 文档里不许出现 `chrome.storage`**、**各个页面发出的消息 Service Worker 都必须有对应处理**、**提示词里的 JSON 示例本身必须是合法 JSON**（这条是真的踩过）。

改动图标后重新生成 PNG：

```bash
node tools/make-icons.mjs
```

## 文件结构


## 隐私

- API Key 和转录结果都只存在本机浏览器的 `chrome.storage.local` 里。
- 插件申请的权限只有 `tabCapture`、`offscreen`、`storage`、`activeTab`、`scripting`、`downloads`，**没有申请 `tabs`**，也不需要「读取所有网站数据」——悬浮条是用 `activeTab` 按需注入的。
- `downloads` 权限只用于「停止录制后自动下载 Markdown」这一个功能，不开启该选项就不会触发任何下载。
- 音频只会发往你配置的 DashScope 地址，不经过任何中间服务器。
- 开启逐段翻译后，**识别出的文本**同样只发往 DashScope 做翻译，不会发给其他任何地方。
- 转录结果保留到你自己点「清空」为止。
